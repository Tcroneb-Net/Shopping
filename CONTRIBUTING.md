# 🤝 Contributing to SOLE & STYLE

Thank you for your interest in contributing to **SOLE & STYLE**! Bug reports, ideas, documentation improvements, and code contributions are all welcome.

SOLE & STYLE is a modern ecommerce storefront for shoes, clothing, and accessories. This guide explains how to contribute.

## Before You Start

- Read the project's `README.md`.
- Check existing issues and pull requests to avoid duplicate work.
- Keep changes focused and explain what they improve.
- Be respectful and constructive in discussions.

## How to Contribute

### 1. Fork and clone the repository

Click **Fork** on GitHub, then clone your fork:

```bash
git clone https://github.com/YOUR-USERNAME/sole-and-style.git
cd sole-and-style
```

Replace `YOUR-USERNAME` with your GitHub username.

### 2. Create a branch

Use a descriptive branch name:

```bash
git checkout -b feature/your-feature-name
```

Examples: `feature/product-details`, `fix/cart-quantity`, or `docs/update-readme`.

### 3. Make your changes

Useful contributions include:

- Improving the interface and responsive layout.
- Fixing bugs in the cart, search, or product filters.
- Improving accessibility and keyboard navigation.
- Optimizing performance and code readability.
- Adding tests and documentation.
- Proposing useful new features.

Keep the existing design direction in mind and avoid unnecessary dependencies.

### 4. Test your changes

Before submitting, check that:

- The website opens in a modern browser.
- Search and category filters work.
- Adding, removing, and updating cart items works.
- Cart totals update correctly.
- The layout works on desktop and mobile.
- Your changes introduce no new browser-console errors.

Explain how you tested your contribution.

### 5. Commit and push

Use a clear commit message:

```bash
git add .
git commit -m "Add: describe your changes"
git push origin feature/your-feature-name
```

Suggested commit prefixes:

| Prefix | Purpose |
|---|---|
| `Add:` | New feature |
| `Fix:` | Bug fix |
| `Update:` | Improvement to existing functionality |
| `Style:` | Visual or CSS change |
| `Docs:` | Documentation |
| `Refactor:` | Code restructuring |
| `Test:` | Tests |

### 6. Open a Pull Request

On GitHub, open a pull request from your branch to the project's main branch.

Include:

- A clear title and description.
- What you changed and why.
- How you tested it.
- Screenshots for visual changes, when useful.
- Related issue numbers, if applicable.

The maintainer may ask for changes before merging.

## Reporting Bugs

Open a GitHub Issue and include:

1. A clear, descriptive title.
2. Steps to reproduce the issue.
3. What you expected to happen.
4. What actually happened.
5. Your browser and device, if relevant.
6. Screenshots or error messages, if available.

Check existing issues before opening a new one.

## Suggesting Features

Open an issue describing:

- The problem or opportunity.
- Your proposed solution.
- How it would benefit users.
- Examples or references, if helpful.

For major changes, discuss the idea with the maintainer before investing significant time in implementation.

## Code Guidelines

- Write readable, maintainable HTML, CSS, and JavaScript.
- Use descriptive names for variables, functions, and CSS classes.
- Keep functions focused and avoid unnecessary duplication.
- Make interactive controls accessible and keyboard-friendly.
- Preserve responsive behavior across screen sizes.
- Never commit passwords, API keys, credentials, or private data.
- Add dependencies only when they provide clear value.
- Use properly licensed assets and provide attribution where required.

## Security Issues

Please do not publish sensitive vulnerabilities, credentials, or private user information in public issues. Contact the maintainer privately through an appropriate channel listed on the GitHub profile or repository.

## License

By contributing, you agree that your contributions may be distributed under the project's license, subject to its terms.

Review the repository's `LICENSE` file before contributing. If no license file exists, ask the maintainer about licensing before submitting work intended for distribution.
